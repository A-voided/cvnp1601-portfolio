I applied several access controls while working on the backup script. I changed the file ownership to root:root so the script was owned by the root account. I also tested the setuid permission using chmod u+s to see if the script would run with root privileges. The ls -l backup.sh output showed -rwsr-xr-x, which proves the setuid bit was successfully applied. However, running the script showed Running as: alice, proving that setuid did not give the shell script root privileges.

The main control is to use a narrow privilege mechanism instead of trying to give the script full root access. A restricted sudo rule or carefully designed helper can allow only the required backup action. The remaining risk is that giving scripts elevated privileges can create a path to unintended root access. The setuid permission should also be removed from the script as a cleanup step.
